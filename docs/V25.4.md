# v25.4 — แก้ "Invalid OAuth state" ตอนล็อกอิน Discord ข้ามโดเมนย่อย (เช่น app.flexozy.xyz)

## สาเหตุของปัญหาในภาพที่ส่งมา
คุกกี้ `oauth_state` (ใช้ยืนยันว่าเป็นคนเดิมที่กดล็อกอิน ป้องกัน CSRF) ไม่มีการตั้งค่า `Domain` มาก่อน — เบราว์เซอร์จึงผูกคุกกี้ไว้กับ
"โดเมนที่ตั้งเป๊ะ ๆ" เท่านั้น ถ้าเริ่มล็อกอินที่ `app.flexozy.xyz` (คุกกี้ถูกตั้งไว้ที่ app.flexozy.xyz) แต่ Discord ส่งกลับมาที่
`flexozy.xyz` (ตามที่เห็นใน URL ของภาพที่แนบ) — คนละโดเมนย่อยกัน เบราว์เซอร์จะไม่ส่งคุกกี้นั้นไปด้วย ฝั่งเซิร์ฟเวอร์เลยหา
`oauth_state` ไม่เจอ → ขึ้น "Invalid OAuth state" ทุกครั้งไม่มีทางผ่านได้เลย

## ทางแก้ (โค้ด — `lib/session.js`)
เพิ่มสวิตช์ `COOKIE_DOMAIN`: ถ้าตั้งไว้ คุกกี้ทั้งหมด (session, oauth_state, fx_pass) จะใช้ร่วมกันได้ทุกโดเมนย่อยของโดเมนหลัก
ไม่ตั้งค่านี้ = พฤติกรรมเดิมทุกอย่าง (ผูกกับโดเมนที่ตั้งเป๊ะ ๆ)

## ต้องตั้งค่าเพิ่ม (สำคัญ — โค้ดแก้ได้แค่ครึ่งเดียว อีกครึ่งต้องตั้งเอง)
1. **ตั้ง `COOKIE_DOMAIN=flexozy.xyz`** (apex โดเมน ไม่มี `https://`, ไม่มี `app.`/`api.` นำหน้า) ใน environment variables ของโปรเจกต์
2. **เลือกโดเมนเดียวให้ Discord callback ชี้ไปแน่นอน** แล้วตั้งให้ตรงกันทั้ง 2 ที่:
   - `DISCORD_REDIRECT_URI` ใน environment variables (เช่น `https://app.flexozy.xyz/api/auth/discord/callback`)
   - Discord Developer Portal → แอปของคุณ → OAuth2 → Redirects → ต้องมี URL **เดียวกันเป๊ะ ๆ** ตัวอักษรต่อตัวอักษร (รวม https://, ไม่มี/มี trailing slash ต้องตรงกัน)
   ถ้าสองค่านี้ไม่ตรงกัน Discord จะปฏิเสธตั้งแต่ขั้นตอนขอ code เลย (ก่อนจะมาถึงปัญหา state คุกกี้ด้วยซ้ำ)
3. ถ้าต้องการให้ล็อกอินได้จากทั้ง `flexozy.xyz` และ `app.flexozy.xyz` พร้อมกัน ต้องเพิ่ม Redirect URI ทั้ง 2 แบบใน Discord Developer Portal
   (Discord รองรับหลาย Redirect URI ต่อแอปเดียวได้) แต่ `DISCORD_REDIRECT_URI` ในฝั่งเราเลือกได้ค่าเดียวต่อ 1 การ deploy — แนะนำให้ใช้
   `app.flexozy.xyz` เป็นหลักตามที่คุยกันไว้ และทำให้ `flexozy.xyz` (ถ้ายังมีคนเข้า) redirect ไป `app.flexozy.xyz` แทนไปเลยเพื่อตัดปัญหา

## ทดสอบแล้ว
- `next build` ผ่านทั้งโปรเจกต์
- โค้ด sign/verify คุกกี้ไม่เปลี่ยน (ยังปลอดภัยเหมือนเดิม) แค่เพิ่ม attribute `Domain` เมื่อตั้งค่าไว้เท่านั้น
- ยังไม่ได้ทดสอบกับ Discord OAuth จริงข้ามโดเมนย่อย เนื่องจากต้องมีโดเมนจริง + ตั้งค่า Discord Developer Portal ประกอบกัน
