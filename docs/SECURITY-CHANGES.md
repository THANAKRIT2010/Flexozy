# ช่องโหว่ที่ปิด (v9)

## ร้ายแรง
1. Hub ใช้รหัสผ่านฝังในสคริปต์ (`Flexozy` / `admin`) → ตรวจ key กับเซิร์ฟเวอร์ (`/auth` scope `login`) ผูก HWID/เพิกถอนได้
2. Auto Run ทำงานก่อนยืนยัน key (ข้าม login) → เริ่มหลังผ่านการยืนยันเท่านั้น
3. ลิงก์ที่บังคับ key ยังดูซอสได้ผ่าน `/api/vault/CODE/unlock` → ปิด (เฉพาะเจ้าของ/แอดมิน)
4. Telemetry ไป `http://78.154.103.8:15218` พร้อมรหัสลับ `LUADER` ฝังในสคริปต์สาธารณะ (ส่ง userId/ชื่อ/เกมแบบ HTTP) → ลบ (ไม่มีในไฟล์ UI ที่แนบ)
5. Code Viewer ใน loader แสดงซอสที่ซ่อนไว้ → ลบ (ไม่มีในไฟล์ที่แนบ)
6. ปลอม IP ด้วย `CF-Connecting-IP` เลี่ยง rate limit / BLOCK_IPS → เชื่อเฉพาะเมื่อมาจาก IP Cloudflare จริง
7. `/bootstrap-source` เรียกตรงได้ทุกโดเมน → ปิดบนโดเมนเว็บ + token ใช้ครั้งเดียวบนโดเมน API
8. SESSION_SECRET fallback เป็น `DISCORD_CLIENT_SECRET` / ค่าเดาได้ → production ต้องตั้ง >= 32 ตัวอักษร ไม่งั้น 503

## ปานกลาง
9. Session cookie ไม่มี exp ในตัว + เทียบลายเซ็นไม่ constant-time → แก้
10. HWID ผูกแบบ read-then-write (race) → HSETNX atomic
11. views เขียนทับทั้งเอกสาร ทำให้ `needs_key` ที่เพิ่งแก้ถูกเขียนทับกลับได้ → ตัวนับแยก (HINCRBY)
12. SSRF จาก URL สคริปต์ที่แอดมินตั้ง → `lib/safeFetch.js`
13. Rate limit / nonce fail-open เมื่อ KV ล่ม → นับในหน่วยความจำแทน
14. ไม่มี rate limit เดารหัสผ่านลิงก์ / สร้างลิงก์ / ping → เพิ่มแล้ว
15. CSRF: ตรวจ Origin ทุกคำขอแก้ข้อมูล + กัน logout CSRF
16. OAuth ขอ scope `email` ที่ไม่ได้ใช้ → ตัดออก
17. Cloudflare แคช response ที่มี token → no-store ทุกชั้น
18. ไม่มี security headers → `next.config.js`
19. ชื่อแมพ/alias ลง Lua ด้วย JSON (`\uXXXX` ทำ loader พังทั้งก้อน) → `luaStr()`
20. โหมดไฟล์: `getVault('constructor')` คืน prototype → hasOwn + เขียนไฟล์ atomic

# v11 — ลิงก์ทั่วไปใช้ระบบเดียวกับ loader + กันบอทที่ยิง request เหมือน Roblox + แก้ลิงก์ได้

## ต้นเหตุที่บอท/สคริปต์ดึงซอสได้ (พบจากการอ่านโค้ด)
1. **`/auth` ไม่มีทางแยกว่าใครยิง** — ขอ key อัตโนมัติ (`AUTO_KEY` เปิดเป็นค่าเริ่มต้น) แค่ POST `{key:"", hwid:"<สตริงอะไรก็ได้ ≥8 ตัว>", scope:"hub:ID"}` ก็ได้ key + token + ซอส ไม่ต้องรัน Roblox เลย
2. **`/raw/CODE` → `/stage/CODE`** ใครก็ GET สองครั้งต่อกันได้ซอส (token ไม่ผูก IP, stub อ่านออกทั้งหมด)
3. **Guard ฝั่ง Lua ข้ามได้ด้วย thread** — ตัวเช็คอยู่ใน loop เดียว ฮุก/ฆ่า loop แล้วเช็คหยุด

## สิ่งที่เพิ่ม
1. **Proof-of-Execution** (`lib/proof.js`) — เซิร์ฟเวอร์ฝังโปรแกรม Lua สั้น ๆ ที่ *สุ่มใหม่ทุกครั้ง* (ค่าคงที่ / ลำดับคำสั่ง / ชื่อตัวแปรต่างกัน, ใช้ `bit32` + `typeof(game)` + `GetService`) ลงใน hub และ stub ; client ต้องรันแล้วส่งผลกลับ (`sc`+`pf` ที่ `/auth`, `p` ที่ `/stage`) เซิร์ฟเวอร์คำนวณคำตอบจาก nonce เอง (ไม่เก็บ state) — **ไม่ได้รัน Lua = 403** ปิดช่อง AUTO_KEY ที่บอทขอ key ฟรีด้วย
2. **ลิงก์ทั่วไป (/raw) ใช้ชุดเดียวกับ /loader** — stub ถูกซีล (guard + ตัวถอดรหัส + ข้อมูลสลับ), token `/stage` ผูก IP + ใช้ครั้งเดียว + ต้องมี proof, ตัวนับ "หนี้" (`RAW_DEBT_MAX`) ดึงรัว ๆ ไม่ตามไป /stage = แบน IP ชั่วคราว, rate limit `/raw` `/stage` 40/นาที
3. **Guard thread** — เก็บ reference ตัวจริงตั้งแต่บรรทัดแรก, เช็คว่า `task.*` / `coroutine.*` ไม่ถูกฮุก/แทนที่, **watchdog 2 ทาง** (loop + Heartbeat) นับรอบของกันและกัน ฆ่าทางใดทางหนึ่ง = อีกทางเตะ (ใช้ตัวนับรอบ ไม่ใช้เวลา → ผู้เล่นมือถือสลับแอปไม่โดนเตะผิด) ; `lua/FlexozyGuard_v2.lua` คือชุดเดียวกันแบบวางหัวสคริปต์เองได้ + `Guard.assert()` ติดจุดสำคัญ
4. **Hub ไม่จำกัดแมพ** — เอาเช็ค PlaceId ก่อนรันออกทั้งการ์ดและ Run by Name ; กดแมพไหนก็รันได้
5. **แก้ลิงก์ได้** — `GET/PATCH /api/vault/CODE` (เจ้าของหรือแอดมิน): แก้โค้ด / ชื่อ / ตั้ง-เปลี่ยน-ลบรหัสผ่าน, แอดมินสลับ `needs_key` ; ปุ่ม "แก้ไข" ในหน้าหลัก (ลิงก์ของฉัน) และหลังบ้าน ; ลิงก์เดิมใช้โค้ดใหม่ทันที, รหัสผ่านสร้าง salt ใหม่ทุกครั้ง

## ข้อจำกัด (พูดตรง ๆ — อย่าเชื่อเอกสารที่สัญญาว่า "กันได้ 100%")
- **ทุกอย่างที่ส่งไปให้ client ถูกจับได้เสมอ** — ผู้ใช้คุมเครื่องตัวเอง hook `loadstring` แล้วเห็นซอสตอนรัน ; Guard ฝั่ง client ลบออกจากสำเนาของตัวเองได้
- Proof-of-Execution ฆ่าบอทที่ "ยิง HTTP เลียนแบบ" แต่ผู้โจมตีที่เขียนตัวรัน Lua + จำลอง Roblox (`bit32`/`typeof`/`GetService`) ได้ยังผ่าน — เป็นการเพิ่มต้นทุน ไม่ใช่ทำให้เป็นไปไม่ได้
- **ลิงก์ทั่วไปที่ไม่ใช้ key** ใครรัน Lua ได้ก็ดึงซอสได้เสมอ — ของที่สำคัญให้ใช้ `needs_key` (หรือ `KEY_ALL_LINKS=1`) และตั้ง `AUTO_KEY=0` ถ้าไม่อยากแจก key ฟรี
- IP ผูกกับ token: ผู้ใช้มือถือที่ IP เปลี่ยนกลางทางจะได้ `bad_challenge` ให้รัน loader ใหม่ (ปิดด้วย `BOOT_BIND_IP=0`)

# v12 — ซีลทั้งก้อน (ไม่มี Lua อ่านได้หลงเหลือ) + กันบอทวิเคราะห์สคริปต์ + แก้ไขไม่ต้องเลื่อนหา

## ต้นเหตุ (จากภาพที่ผู้ใช้ส่งมา)
บอทดิสคอร์ด (".get URL" ของ "The Devirtualizer"/SynCrypt) ยิง `GET /raw/CODE` ตรง ๆ แล้วได้ **Lua อ่านได้เต็ม ๆ** กลับมา (`local STRICT = true`, `game:GetService("Players")` ฯลฯ) เพราะ v11 ส่ง guard ตัวนอกเป็นข้อความเปล่าก่อนค่อยซีลส่วนที่เหลือ — เครื่องมือวิเคราะห์เลยสรุปว่า "plain Lua / open-source code, not obfuscated"

## สิ่งที่แก้
1. **ซีลทั้งก้อน** (`lib/seal.js`, `lib/stubSource.js`, `lib/vault.js`) — guard ตัวนอกไม่ส่งเป็นข้อความเปล่าอีกต่อไป รวมเข้ากับส่วนที่เหลือแล้วเข้ารหัสเป็นก้อนเดียว เหลือแค่ตัวถอดรหัสทั่วไป (ไม่มีคำว่า Flexozy/guard/game ใด ๆ) ก่อนหน้านี้
2. **ตัวถอดรหัสสุ่มใหม่ทุกคำขอ** — ชื่อตัวแปรทุกตัว (2-4 ตัวอักษร) + ตารางสลับอักษร 64 ตัว (ไม่ใช่ base64 มาตรฐาน) ต่างกันทุกครั้ง เทียบ response สองครั้งจะไม่เจอ byte/ชื่อซ้ำเดิมเลย แก้ปัญหาการจับลายเซ็นแบบ static ที่เครื่องมืออย่าง SynCrypt ใช้
3. **ขยายรายชื่อบอทที่บล็อก** (`lib/bots.js`) — เพิ่มคำที่เกี่ยวกับเครื่องมือวิเคราะห์/ถอดรหัสสคริปต์ (devirtualizer, deobfuscator, decompiler, syncrypt, ฯลฯ) แต่ยังมีข้อจำกัดเดิม: ถ้าบอทปลอม User-Agent เป็น "Roblox/WinInet" ตรง ๆ การเช็ค UA เพียงอย่างเดียวแยกไม่ออก — ของที่กันได้จริงคือการซีลทั้งก้อน (ข้อ 1-2) ทำให้ต่อให้ดึงไปได้ก็ไม่เหลือข้อมูลให้วิเคราะห์
4. **แก้ไขลิงก์แบบเต็มจอทันที** (`components/EditLink.js`) — เปลี่ยนจาก modal ที่ต้องเลื่อนหาปุ่มบันทึก เป็นหน้าเต็มจอ เปิดมาเห็นโค้ด/ปุ่มบันทึกทันที (ปุ่มบันทึกอยู่แถบบนตลอด ไม่ต้องเลื่อน) และล็อกสกอลหน้าหลังไว้ระหว่างแก้ไข

## ข้อจำกัด (พูดตรง ๆ)
- **นี่คือ obfuscation ไม่ใช่การเข้ารหัสที่ถอดไม่ได้** — ผู้โจมตีที่เขียนสคริปต์ถอดรหัส XOR+base64-variant เองได้ (อัลกอริทึมไม่ซับซ้อน) ยังถอดได้เสมอ สิ่งที่เปลี่ยนคือ **เครื่องมือสแกนอัตโนมัติที่ใช้ลายเซ็น/รูปแบบคงที่** (เทียบกับฐานข้อมูลของ "โค้ดที่รู้จัก") ใช้ไม่ได้ผลอีกต่อไป เพราะไม่มีอะไรคงที่เหลือให้จับคู่
- ของที่ "ใช้ได้จริง" (เกมสคริปต์จริง) ยังถูกกันด้วย key + HWID + proof-of-execution เหมือนเดิม — ชั้นนี้แค่ทำให้ตัวโหลด/ลิงก์ทั่วไปที่หลุดออกไปไม่มีประโยชน์ต่อการวิเคราะห์

## ทดสอบจริง (รันแล้ว)
ตัวถอดรหัส 20 แบบสุ่ม (ชื่อตัวแปร+ตารางอักษรต่างกันทุกตัว) รันบน Lua จริงแล้วถอด+รันถูกต้องทั้งหมด (รวมข้อความไทย UTF-8) · จำลองบอทยิง `/raw/CODE` ตรง ๆ ด้วย UA `Roblox/WinInet` — response ไม่มีคำว่า `Players`, `game:GetService`, `FxApi`, `Flexozy`, `task.spawn` หรือชื่อตัวแปรที่อ่านออกเลยแม้แต่ตัวเดียว · regex บล็อก UA ที่มีคำว่า devirtualizer/syncrypt ได้ถูกต้อง ไม่กระทบ UA ปกติ/Roblox · รันชุดทดสอบ v11 ทั้ง 20 + 13 ข้อซ้ำผ่านหมดหลังเปลี่ยนมาใช้ตัวถอดรหัสแบบสุ่ม

# v13 — ซีลซ้อน 2 ชั้น, UI แก้ไขแบบตัวแก้โค้ด (เลขบรรทัด + Ctrl/Cmd+S)

## คำถาม "ล็อกด้วย VM หนักเต็มระบบ เกะไม่ได้ กัน AI/บอทเข้าเว็บ"

**สิ่งที่พบว่ามีอยู่แล้วในโปรเจกต์** (ไม่ได้เพิ่มใหม่ แค่ตรวจสอบและยืนยันว่าทำงาน): เว็บหลัก (หน้าแรก, หลังบ้าน, ทุกหน้า HTML) ถูกล็อกด้วยกำแพง proof-of-work + Cloudflare Turnstile (ถ้าตั้ง key) อยู่แล้ว (`lib/challenge.js`, `lib/pass.js`) — บอทหรือ AI ที่ไม่รัน JavaScript จะได้ 403 ทันทีจาก `BOT_RE` ที่ครอบคลุม GPTBot, ClaudeBot, anthropic, Perplexity, Google-Extended ฯลฯ อยู่แล้ว ส่วนบอทที่ปลอม UA เป็นเบราว์เซอร์จะต้องแก้โจทย์ SHA-256 proof-of-work (และ/หรือ Turnstile) ก่อนถึงจะได้คุกกี้เข้าเว็บ ทดสอบแล้วใช้งานได้จริง (ดูหัวข้อทดสอบด้านล่าง)

**สิ่งที่ *ไม่* ถูกล็อกด้วยระบบนี้**: `/loader`, `/raw`, `/stage`, `/auth`, `/bootstrap-*` — endpoint ที่ Roblox executor ต้องเรียกได้ตรง ๆ (Roblox HttpGet รัน JavaScript ไม่ได้ แก้โจทย์ captcha ไม่ได้) จุดนี้กันด้วยคนละระบบ: proof-of-execution + token ผูก IP + ซีล (v11-v12)

## สิ่งที่เพิ่มในรอบนี้
1. **ซีลซ้อน 2 ชั้น (DOUBLE_SEAL)** — `/loader` และลิงก์ทั่วไปตอนนี้เข้ารหัส 2 รอบซ้อนกัน (คนละชื่อตัวแปร คนละตารางอักษรในแต่ละชั้น) เพิ่มรอบที่เครื่องมือวิเคราะห์อัตโนมัติต้องถอดก่อนเจอ Lua จริง
2. **หน้าต่างแก้ไขลิงก์ดีไซน์ใหม่** (`components/EditLink.js`) — เลขบรรทัดซิงก์กับการเลื่อน, จุดสีบอกว่ามีการแก้ไขที่ยังไม่บันทึก, กด Ctrl/Cmd+S บันทึกได้เลย, แถบด้านข้างแยกเป็นการ์ดชัดเจน

## ข้อเท็จจริงที่ต้องพูดตรงๆ (สำคัญ)
- ไม่มีระบบไหนที่ "เกะไม่ได้" จริงๆ ถ้ามันต้องรันบนเครื่อง/executor ของคนอื่น โค้ดที่ส่งไปให้เขาต้องรันได้ ซึ่งแปลว่าต้องมีจุดที่ถอดรหัสเป็น Lua จริงเสมอ คนที่เข้าใจอัลกอริทึมเขียนตัวถอดเองได้เสมอไม่ว่าจะซ้อนกี่ชั้น สิ่งที่ชั้นพวกนี้ทำได้จริงคือเพิ่มต้นทุน/เวลาให้คนทั่วไปและทำให้เครื่องมือสแกนอัตโนมัติที่มองหาแพทเทิร์นคงที่ใช้ไม่ได้ผล ไม่ใช่ปิดประตูทั้งหมด
- "VM" ในความหมายจริง (custom bytecode interpreter แบบ Luraph/MoonSec) คือการสร้างภาษาโปรแกรมใหม่ทั้งภาษาพร้อม compiler เป็นงานวิศวกรรมขนาดใหญ่มาก ไม่ได้สร้างของแบบนี้แบบรีบๆ ให้ เพราะถ้าทำพลาดจะมีบั๊กที่ทำให้สคริปต์รันไม่ได้บนบางเครื่อง ซึ่งแย่กว่าไม่มี ถ้าต้องการจริงๆ ควรเป็นโปรเจกต์แยกที่ทดสอบอย่างละเอียดกว่านี้
- กำแพงกัน AI/บอทที่หน้าเว็บมีประสิทธิภาพสูงอยู่แล้ว (ไม่ใช่ของใหม่) สิ่งที่ยังหลุดได้คือ AI agent ที่ควบคุมเบราว์เซอร์จริง (รัน JS ได้ แก้ captcha เองไม่ได้ถ้ามี Turnstile แต่ proof-of-work ธรรมดาแก้ได้ถ้าเขียนโค้ดรองรับ) ถ้าต้องการกันเพิ่มแนะนำตั้ง `TURNSTILE_SECRET_KEY` + `NEXT_PUBLIC_TURNSTILE_SITE_KEY` ให้ใช้ Cloudflare Turnstile จริงแทน PoW เฉยๆ

## ทดสอบจริง (รันแล้ว)
หน้าเว็บหลัก: UA python-requests / GPTBot / ClaudeBot → 403 ทันที (ไม่เห็นหน้าเว็บเลย) · UA เบราว์เซอร์จริงที่ยังไม่มีคุกกี้ fx_pass → ได้หน้า "กำลังทำการตรวจสอบความปลอดภัย" (403 พร้อมหน้า JS proof-of-work) ไม่ใช่เนื้อหาเว็บ · `/raw` และ endpoint ของ executor ยังเปิดใช้งานได้ปกติ (ตามที่ต้องให้ Roblox เรียกได้) · ซีลซ้อน 2 ชั้น ถอด+รันถูกต้องบน Lua จริง · รันชุดทดสอบเดิมทั้งหมด (20 + 13 ข้อ) ซ้ำผ่านหมดหลังเปิด double-seal
