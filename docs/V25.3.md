# v25.3 — แก้ไข: ไม่ออกคีย์อัตโนมัติ ต้องติดตาม YouTube + เข้าร่วม Discord ก่อน
(แก้จาก v25.2 ที่เข้าใจผิดว่าให้ออกคีย์ทันทีตอนล็อกอิน)

## สิ่งที่เปลี่ยน
- `lib/auth.js`: เอาการออกคีย์อัตโนมัติตอนล็อกอินออกแล้ว ล็อกอินแล้วแค่เข้าสู่ระบบ + เข้าร่วม Discord อัตโนมัติ (ของเดิม) เท่านั้น ยังไม่ได้คีย์
- `lib/keys.js`: เพิ่ม `checkDiscordMember(discordId)` — เช็กจริงผ่าน Discord Bot API (`GET /guilds/{id}/members/{id}`) ว่าอยู่ในเซิร์ฟเวอร์จริงไหม ไม่เชื่อฝั่ง client
- `app/api/me/key/route.js` (POST): ต้องส่ง `{youtube:true}` (ผู้ใช้ยืนยันเอง) **และ** ต้องเป็นสมาชิก Discord จริง (เช็กสดทุกครั้ง) ถึงจะออกคีย์ให้ ขาดอันไหนไม่ได้คีย์
- `components/MyKeyPanel.js`: เปลี่ยนจากปุ่ม "เคลม" ปุ่มเดียว เป็นเช็กลิสต์ 2 ขั้นตอน (ลิงก์ไปติดตาม YouTube + ลิงก์เข้าร่วม Discord + ช่องยืนยันตัวเอง) ก่อนปุ่ม "รับคีย์" จะกดได้

## ข้อควรรู้ (บอกตรง ๆ): การยืนยัน YouTube เป็นระบบ honor-system เท่านั้น
ฝั่งเซิร์ฟเวอร์ไม่มีทางตรวจสอบจริงได้ว่าผู้ใช้กดติดตาม YouTube จริงหรือไม่ โดยไม่ให้ผู้ใช้ล็อกอิน Google เพิ่มอีกบัญชี (ต้องมี Google Cloud project,
เปิด YouTube Data API, ขอ scope อ่าน subscriptions ซึ่ง Google อาจต้องรีวิวแอปก่อนใช้งานจริงกับคนทั่วไป — ใช้เวลาหลายวันถึงหลายสัปดาห์)
ตอนนี้จึงเป็นแค่การ "กดยืนยันเอง" (เหมือนเว็บแจกคีย์ทั่วไปส่วนใหญ่ทำกัน) ส่วน **เข้าร่วม Discord ตรวจสอบจริง** ผ่านบอทเสมอ ปลอมไม่ได้

ถ้าต้องการให้ YouTube ตรวจสอบได้จริงด้วย ต้องสร้าง Google Cloud OAuth app เอง แล้วบอกมา จะช่วยต่อระบบให้

## ตั้งค่าที่ต้องมี
- `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID` — จำเป็น ไม่มีจะออกคีย์ไม่ได้เลย (ระบบจะแจ้ง "discord_not_configured" ชัดเจน ไม่ใช่โทษผู้ใช้ว่าไม่ได้เข้าร่วม)
- `YOUTUBE_CHANNEL_URL`, `DISCORD_INVITE_URL` — ลิงก์ที่โชว์ให้ผู้ใช้กด (ไม่ใส่ก็ยังใช้งานได้ แค่ไม่มีปุ่มลิงก์โชว์)
- `DISCORD_KEY_DAYS` (ค่าเริ่มต้น 30), `DISCORD_KEY=0` ปิดทั้งระบบ

## ทดสอบแล้ว
- โค้ดทุกไฟล์ที่แก้ผ่านการตรวจไวยากรณ์และ `next build` ทั้งโปรเจกต์
- `discordBotConfigured()`/`checkDiscordMember()` คืนค่า false อย่างปลอดภัยเมื่อยังไม่ตั้งค่าบอท (ไม่ออกคีย์ให้มั่ว ๆ)
- ยังไม่ได้ทดสอบกับ Discord bot จริงและ session ผู้ใช้จริงแบบ end-to-end
